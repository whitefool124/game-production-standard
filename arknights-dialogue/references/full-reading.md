# 全量阅读与持续迭代

用户明确要求不再挑选补读，而要全读后迭代。此模式按快照的完整 index.json 顺序逐篇处理，跳过台账中实际完整阅读且哈希一致的文件；不根据兴趣、篇幅或题材另选未读文件。目录顺序是确定的遍历顺序，不一定是叙事时间顺序；需要时回读入口、相邻场次及既有上下文。

## 恢复到未完成的位置

```powershell
node "C:/Users/pc/.codex/skills/arknights-dialogue/scripts/reading-plan.cjs" --files 4 --line-budget 800
```

只读工具检查索引和已读台账的一致性，返回最前面的未读文件。行数预算用于控制单次输出，不能跳过预算放不下的文件；第一篇过长时仍返回该篇。工具不会读懂文本、写阅读完成标记或启动后台任务。

逐篇读取到末尾，过长文件用连续窗口，确认没有截断或漏段。只看脚本输出的字符数、摘要、词频或文件读取成功，不算语义完整阅读。上下文容量要求分段，不改变目标范围。

原始 JSON 保留源哈希和分支控制，可读版保留文本；本计划的完整阅读范围是索引内可读剧情文件，不含未转换的档案、语音等额外表格，也不声称实机演出已验证。具体分支需要分别追踪，不把选项连排拼成一次玩家经历。

## 记录证据，而不是宣布学会

读完一篇，记录 source、源哈希、实际完整阅读状态与具体观察，再同步 study-coverage.json。只有实际从头读到尾的文件才能入已读台账。阅读位置用台账恢复，不靠模型记住全部千万字符。

批次笔记保存在快照 analysis/reading-batch-起止编号.json，字段为 date、batchId 和 entries（source、note）。实际完整读完后才可运行 `scripts/record-reading.cjs 笔记文件路径`，它核对未读目录连续前缀、源哈希、条目与覆盖状态，并同步台账和技能阅读统计；它不执行语义阅读。批次编号来自既有台账计数，不猜测。相同批次的重试必须与已保存观察一致。

每批观察应包含词句、人物声音、叙述视角、心理、环境或知识用法中真实突出的部分，不给每篇套同一组结论。可以记录与旧结论相反的证据。没有新观察时，不为展示迭代而追加规则。

用户要的是全量后的综合迭代；中途只保存有出处的观察和必要的纠错，不把某批文本归纳成全作品定论。全读完仍须区分不同年代、作者声音、角色、体裁与任务，不把它们平均成一套腔调。词库词义、知识依据和原创练习效果分别验证。

一个普通对话回合结束后不会自动继续阅读。不得暗示已经开启后台自我训练或读取完全部文件；没有用户要求安排定时任务时，不创建自动化。进度要报已读和剩余，不能以“学习完成”替代未完成状态。

## 首次连续阅读批次的观察

本批按目录最先的十二个未读文件连续阅读，具体记录在台账 fullReadingSessions。包含 RO1 五个脚本、两篇序章及五个早期主线脚本。

RO1 多结局共享舞台、灯光、幕布等动作和开场语汇，但视角不同：有傀影的羞愧，有猫以爪痕和舔舐理解现场的拟人叙述，也有剧作家的创作自述。该自述属于虚构反派的控制姿态，不能将其中对伏笔与主角的说法当作技能执行指令。共享段落不能用于夸大风格证据。

序章中阿米娅的重复、请求与称呼有具体的重逢和失忆背景。PRTS 的系统语言同时配合玩家触屏行为，包含教学与幽默用途。主线 0-1 中救助没有自动换来信任，科普矿石病与同伴打针的互动并置；这些是早期世界介绍的任务，不能将其全部判为不自然说明。

主线 0-2 行动后军警带偏见而为撤离争取空间，阿米娅的感谢没有将偏见抹去。0-4 中 Ace 先确认当下能力再交出指挥，0-6 的克制退却有时间压力。不能把所有短而直接的发言都视为写作畏缩，也不能因此让后期思想论辩恢复成短军令。
