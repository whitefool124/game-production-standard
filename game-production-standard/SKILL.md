# 游戏制作规范

按 [正式规范](references/game-production-standard.md) 执行当前任务相关条目。按改动范围选用对应章节。项目已定的引擎、素材、输入和交付规则优先，局部修改只读相关专项。

## 执行要点

1. 以玩家当前决策组织图形、空间、操作与反馈。最大限度克制说明文字，保留必要命名、精确规则、关键风险、叙事和无障碍文本。
2. 使用独立控件和真实布局。禁止连续空格、制表符、空行或人工断行冒充排版；禁止圆点、竖线及近似字形充当游戏界面分隔符。代码运算符、语义换行和有意义的游戏图形不在禁令内。
3. 正式布局至少完成一条设计路径：宿主内置生图参考的实际查看与审阅，或适用前端设计技能的实际应用与画面审阅。有效既有参考可复用。未完成任一路径的页面只能标为临时原型；正式任务应继续实现和验证，不得自行降级交付。按 UI-07 检查，调用工具不等于合格。
4. 禁止无意义装饰、陌生图标强行省字、仅靠颜色区分关键状态、缩小文字硬塞内容及重复说明。按 UI 与 TXT 章节检查适用状态和显示条件。
5. 数值、按键提示与成功反馈来自真实权威状态。禁止假成功、无理由等待、重复扣费、无功能入口和隐藏错误冒充修复，按 DEV 章节核验。
6. 所有游戏对白的创作、改写、翻译与审阅必须先使用 `arknights-dialogue`，包括 NPC、剧情、分支选项、喊话与过场。服从项目世界观、角色、字符串格式和交付语言；普通 UI 提示不套剧情文风。对白分行不代替控件布局。
7. 新做或重做玩法时，先用一个可玩的代表流程验证玩家入口、决策、规则结果和后续状态，再批量扩展同类内容。关键数据改动与跨层故障按 DEV-06 核对实际写入和读回。
8. 按改动风险集中验收当前版本。历史复审按 QA-04 对齐版本、页面、触发和状态，区分本轮通过、历史通过、失败、部分验证、未测、无法复核和不适用。静态图的结论限于所展示的画面。

## 按需协作

- **正式界面**按 UI-07、UI-08。建立或改造视觉方向时，技能路径优先用 `frontend-design` 明确项目视觉语言，再按需用 `game-ui-design` 或引擎 UI 技能落实。生图参考仍是有效路径，局部修复可沿用有效设计。
- **资产替换**按 DEV-07 检查实际引用、项目规格和运行表现。
- **音效**按 AUD-01 至 AUD-03。寻找现成音效时优先用 `sound` 做 Freesound 检索与候选下载。接入及混音按需用 `game-sound-design` 或 `audio-design`。服从项目对真实录音、现成电子音和许可的要求。
- **交互动效**按 MOT-01、MOT-02。参考 Emil Kowalski 和 Jakub Krehel 的交互方法，原生游戏用项目现有实现。**PV、开场与动态图形**按 MOT-03，使用项目演出技能，浏览器独立动效可用 `bang-motion`。

`arknights-dialogue` 为对白任务的独立依赖，本包不含其原作语料。使用前通过当前技能目录找到并读取该技能；缺失时明确报告依赖缺失，不伪称已使用或编造语料来源，并继续可独立完成的工作。其他设计技能按所选路径提供，不要求同时安装全部技能。

## 交付

简要说明交付阶段、所用设计依据、完成结果、当前证据与剩余限制。普通审阅由执行者完成，不新增用户确认门槛；用户明确要求亲自审图时遵从其要求。任务范围与授权仍由当前会话决定。
